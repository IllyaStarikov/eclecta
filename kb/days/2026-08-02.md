### [A Week in Matrix](https://piegames.de/dumps/a-week-in-matrix) — 6/10

If you run a Matrix community, this is the failure catalog you inherit: silent IPv6-dropping federation, split-brain permission desyncs, and ban lists with no local override short of unsubscribing the whole community.

Notes: Spaces are implemented as ordinary rooms, so a stray message notifies every member; most clients don't auto-restrict chat permissions, and the author had to edit permissions manually via Element's devtools. · Dendrite's default config silently drops all egress IPv6 traffic, which broke the Draupnir moderation bot's outbound federation and left the space unprotected for over a month before the cause was found. · Subscribed community policy rooms (m.policy.rule.server / m.policy.rule.user) banned a user's whole domain over past open-registration spam; there is no local override, so the only remedy was unsubscribing the entire list and re-exposing the community to spam. · Debugging the ban took ~40 minutes because Element only searches m.messages events; the workaround was exporting the room to HTML and grepping, which surfaced seven hits. · Permission changes desynced across homeservers, producing a split-brain room where servers on one side soft-fail messages invisibly to the other; the workaround was having a user on a different homeserver reapply the change and hope it propagates. · Migrating between homeserver implementations (Dendrite to Synapse) has no satisfying solution, so communities stay stuck on a deprecated server whose recent commits are mostly dependency bumps.
