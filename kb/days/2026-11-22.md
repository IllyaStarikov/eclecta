### [Decompiling Fast Food Tycoon 2: Drawing the World](https://healeycodes.com/decompiling-fast-food-tycoon-2-drawing-the-world) — 6/10

An LLM agent, given Ghidra output, live process memory, and a patched message handler, reconstructed a 2001 game's entire rendering and simulation logic without ever editing the executable on disk, a concrete template for agent-driven reverse engineering.

Notes: Toolchain: Ghidra decompiled fastfood2.exe's 4,046 functions into ~9.5MB of C-like text (addresses, field offsets, constants, calls), loaded into SQLite and wrapped with a decomp_index.py script for grep, callers, and string queries; the author drove a self-described GPT-6.1 Sol Medium agentic loop. · Live inspection: the agent used Windows ReadProcessMemory to read running values (cash, camera position, selected building) and traced the decompiled functions that wrote those addresses; it patched the Windows message handler to inject clicks and camera moves on the game's own UI thread, leaving the on-disk binary untouched. A UI crawler mapped the remaining unknown controls. · Renderer: dirty-region repainting limits redraws, cells are visited diagonally/isometrically across multiple passes, and hidden characters are kept visible by marking their shape with a temporary pixel value, then outlining covered body parts (yellow) and thought icons (white). Each pixel stores a 16-bit color plus a separate lighting byte, combined with a dither pattern only at final draw. · Lighting: a 25-entry hourly table ranges from 70 at night to 251 at day; lamp on/off thresholds stagger via `light <= 160 + (lamp.id & 7)`, so default standard lamps switch on ~18:25-18:30 and off ~05:35-05:40. Pizzerias use paired sprite files, a light mask (.m.spr) kept per-pixel as the brighter of two values and night window colors (.l.spr), so signs and windows stay lit while the building darkens. · Simulation details (author claims from decompiled code): citizen schedules persist across days rather than resetting; walker speeds differ (errand boy 27px/s, tourist 16.2px/s, celebrity 13.8px/s); pizza scoring splits each pie into 24 regions, checks topping symmetry and ingredient pairings per customer group, and runs a plagiarism check on ingredient weights that flags copied recipes as 'not original', costing +30 taste points for yuppies/goths/tourists and +5 for big shots. · Provenance notes: internal strings and animation names are mostly German; a config file labels the game 'Pizza3' (Init-File fuer Pizza3-Stadt); the title is Fast Food Tycoon 2, known in Europe as Pizza Connection 2. The post's generated images reuse the game's own decompiled fonts.

### [Mac at Any Scale](https://namespace.so/blog/mac-at-any-scale) — 6/10

If you run iOS CI or coding agents that need a Mac, this is the operational playbook for renting macOS at scale: 4 Gbps guest networking, two-VM-per-host limits, and multi-hundred-GB Xcode images distributed BitTorrent-style.

Notes: Namespace racks MacBook Pros, not Mac Minis, because Mac Minis ordered in January 2026 arrived in July and lag on CPU updates (Mini skipped M5 for 10 months, then jumped to M6 first); each laptop gets an IP KVM, an external 10G NIC, and four cables, totaling 48 cables plus 12 Ethernet plus KVM wiring per shelf. · Unexpected failure modes: HDMI cables (not MagSafe) were the least reliable connector, to the point they bought out Amazon's entire supply of a good one; FileVault reboot prompts expire after 5 minutes on both KVM screen and Tahoe's SSH remote unlock, forcing a physical reboot-and-race, with `fdesetup authrestart` offered as a workaround that keeps the disk unlocked. · Built on Apple's Virtualization framework (compared to Firecracker), not the lower-level Hypervisor framework, which cannot run macOS; Apple caps macOS to two VMs per physical host regardless of hardware, so even a 24-core/192GB machine is sliced only in half (e.g. 6/12-core instances on 14-core Minis). · Guest networking is routed through a gVisor userspace TCP/IP stack to enforce per-customer policies on untrusted code; every packet crosses an IPC boundary between the VMM and host processes, capping throughput at a claimed 4 Gbps upstream (measured via Fast.com), below line rate. · VM images reach 2 TB across macOS versions, iOS runtimes, and Xcode betas; Namespace stores them sparse and as layered shallow copies in its OCI registry, distributes blocks peer-to-peer (BitTorrent-inspired, but among trusted peers), and materializes them to each node's local SSD using APFS holes and clonefile/`cp -c` rather than slower NBD-backed disks. · A caveat flagged in the text: installing an Xcode beta bumps global CoreDevice/CoreSimulator versions and breaks stable Xcode on the same system, forcing separate image variants with and without pre-release Xcode.

### [Show HN: Esp32sim – Run ESP32 firmware in the browser](https://github.com/mikroverk/esp32sim) — 6/10

You can boot an unmodified ESP-IDF firmware image through the real mask ROM into FreeRTOS in a browser tab, debug it with trace/break/watch, and even hit the real network over a virtual WPA2 AP, with no board, no cloud, and no patched firmware.

Notes: Covers four SoCs: classic ESP32 (dual Xtensa LX6), ESP32-S3 (dual LX7 @240MHz), ESP32-C3 (RISC-V RV32IMC @160MHz), and ESP32-C6 (RISC-V RV32IMAC @160MHz). Each boots real mask ROM to 2nd-stage bootloader to FreeRTOS to app with no stubs or patched firmware. · Speed differs by target: S3 uses a block interpreter plus AArch64 JIT at a reported ~150-240 Minsn/s (roughly 30x real time on hello_world); C3 and C6 use a plain interpreter with no block cache or JIT yet. S3 and C3/C6 are labeled 'mature' and 'draft' respectively. · Hardware validation is explicitly not cycle-exact: S3 checked in JTAG lock-step (reportedly 3000-8000 steps, 0 PC divergence after masking window exceptions and resyncing CCOUNT delay loops); C3 and C6 validated by console diff (205/208 and 203/204 lines identical over three boot cycles, the differences being the ROM 'Saved PC:' line). The author says these comparisons each found five emulator bugs, including a device-command race and a reset-time cycle counter bug. · A virtual WiFi AP lets the unmodified Espressif WiFi blob do scan, auth, association and the WPA2-PSK four-way handshake; a virtual network behind it provides DHCP/ARP/ICMP/DNS/SNTP, and --net nat relays guest TCP/UDP over host sockets for real HTTPS. In-browser WASM builds have no NAT since the browser has no sockets. Reported decoder checks: 977k/161k/126k instructions with 0 mismatches, from earlier manual runs excluded from CI. · Architecture shares most of the SoC across chips: C3 and C6 reuse the S3's UART, USB-Serial/JTAG, timers, GPIO, SPI flash controller, GDMA and SHA/AES/RSA models; only the CPU crates are genuinely separate. The C6 adds an 802.15.4 MAC that answers energy scans and, via --cooja, drives as an external Cooja-NG mote in lock-step with emulated MSP430 nodes. · MIT licensed (copyright Joakim Eriksson, Alice, Mattia Fiumara), written from ESP-IDF register headers, the RISC-V spec and the C3/C6 TRMs; QEMU was consulted for instruction semantics only, no code copied. Live demos run Linux 6.11 on the S3, a SID player, and a '4-bit transformer' fish-steering demo.

### [Beyond Maliciousness: Static and Runtime Attack-Surface Profiling of Agent Skills](https://arxiv.org/abs/2610.19264) — 6/10

Install an agent skill and you grant it your session's privileges: across 6,309 marketplace listings, 70% carry at least one elevated capability and half can run a shell, almost none of it visible at install time.

Notes: Methodology: two-phase profiling of 6,309 listings from two marketplaces (ClawHub, skillsmp), combining whole-bundle static analysis and dependency provenance checks with instrumented sandbox execution plus model-based assessment of traces; listings were selected for execution without conditioning on any prior threat signal. · Capability prevalence (static+runtime measured): 50% show shell-execution capability, 35% filesystem read, 31% filesystem write, 31% network egress, 13% credential access; 7 in 10 carry at least one elevated capability. · Skills are Markdown instruction documents that run with the authority of the session that loaded them; installing grants standing to direct the agent rather than new OS privilege, and that grant is what the paper quantifies. · The permission model is described as 'close to inert': frontmatter only pre-approves tools to suppress confirmation prompts, it does not restrict reach; its vocabulary cannot even express credential or environment access, and nothing checks declarations against the bundle. · Declaration gap: of 6,061 parseable listings only 770 declare anything, and 59% of declaring listings understate actual capability; ClawHub declares roughly 2x as often as skillsmp yet under-declares on 88% of its declarations vs 31% for skillsmp. · Conclusion: marketplace triage cannot rest on declared permissions and must rest on what the bundle can do; capability-oriented attack-surface profiling is framed as a complement to maliciousness detection, not a replacement.
