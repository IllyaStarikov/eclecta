### [StateAct: Program State, before Pixels, for Long-Horizon Computer-Use Agents](https://arxiv.org/abs/2607.22798) — 7/10

A computer-use agent that reads program state through code instead of screenshots lifts Claude Opus 4.8 on OSWorld 2.0 while cutting cost per task roughly 9x, arguing the real bottleneck is reasoning, not pixels.

Notes: Core premise: a screenshot is a lossy render of program state (files, application backends, DOM); different states can produce identical pixels, so the main agent manipulates state directly via code and only delegates screenshot-and-click work to a GUI subagent on subgoals that need it. · GUI interaction is rare: only 28 of 108 OSWorld 2.0 tasks and 1.1% of main-agent steps route through the screenshot subagent. · Self-reported OSWorld 2.0 gains on Claude Opus 4.8: binary success 20.6% to 26.9%, partial success 54.8% to 61.6%, at ~9x lower cost per task than driving the same model with screenshots alone. · Ablation: a code-only variant with no GUI subagent reaches only 45.9% partial success, below the 54.8% screenshot baseline, so both code access and the GUI fallback are needed. · An independent finish gate verifies the saved result for structural failures: output missing, unsaved, or written to the wrong path; fresh subagents take subgoals to keep the main agent's context focused over hundreds of steps. · Numbers are the authors' own on a single model (Claude Opus 4.8) and one benchmark; no external replication or per-task methodology breakdown is provided in the abstract.

Notes: The from-scratch synthesis problem is severe: the paper reports frontier models fully resolve fewer than 1% of ProgramBench tasks, which the authors blame on the absence of scalable training environments covering the full software life cycle rather than a single phase. · MindForge is an automated pipeline that converts open-source command-line programs into 'source-free' environments exposing only a compiled reference executable and its documentation, forcing the agent to reconstruct behavior without seeing source. · Training data is program-synthesis trajectories generated by GLM-5.2 as a teacher agent, built from repositories disjoint from ProgramBench's; fine-tuning Qwen3.6-27B on these raised its ProgramBench average test pass rate from 37.98% to 49.51%, described as comparable to substantially larger frontier models. · Note the two metrics differ: the <1% figure is tasks 'fully resolved,' while 37.98%/49.51% is average test pass rate, so the headline numbers are not directly comparable. · Reported gains transfer to seven unseen benchmarks: +31.00 on RepoZero-C2Rust, +14.16 on DeepSWE, +10.70/+4.56 on NL2Repo-Bench (with/without tests), +5.04 on SWE-bench Verified, +5.93 on SWE-bench Pro, +5.22 on SWE-bench Multilingual, and +4.94 on FeatBench. · All numbers are self-reported in the abstract; the excerpt gives no training compute, trajectory count, ablations, or comparison methodology for the 'comparable to frontier' claim.

### [Why Don't People Use Formal Methods?](https://hillelwayne.com/post/why-dont-people-use-formal-methods) — 6/10

Wayne's economics argument is the takeaway for working engineers: full code proofs cost roughly four lines a day (per Microsoft's IronFleet), so the payoff lives in cheaper wins, partial verification, better testing, and design-level specs, not proving every line.

Notes: Taxonomy the author coins (not standard FM terms): code specification/verification (CS/CV) versus design specification/verification (DS/DV); 'formal specification' in practice usually means specifying and verifying designs, 'formal verification' means code. · Three code-spec camps: independent theorem statements (Isabelle, ACL2, HOL4), embedded pre/postconditions a.k.a. Design by Contract (Hoare Logic, first in Euclid early 1970s; SPARK, Dafny), and dependent types via Curry-Howard (Coq, Agda); the author calls Design by Contract the most popular industrial form. · Contrarian claim, asserted without cited data: most high-assurance software (medical devices, aircraft) does not actually use formal methods; verification (code matches spec) does not deliver validation (spec matches what the client wants). · Cost figures: Microsoft's IronFleet produced ~5,000 lines of verified Dafny in 3.7 person-years, about four lines/day; Cleanroom (docs, flow analysis, heavy review, no proofs or unit tests) is claimed to hit under 1 bug/kLoC in production with equal-or-shorter delivery times. · SMT history: Stanford Validity Checker (1998) then CVC (2002); Microsoft Research's Z3 (2006) made SMT the default for automated proving, largely on usability, after MSR used it on the Windows kernel. · Author's caveats: self-described non-historian who specializes in DS/DV, so code-verification sections are likelier to contain errors; article text cuts off mid-sentence in the design-language section (VDM ~1972; Z, Promela, SDL, Statecharts, Decision Tables listed).

### [The Difference Between a Button and a Link](https://unplannedobsolescence.com/blog/buttons-vs-links) — 6/10

If the Triptych proposal lands, you could implement Cancel, Delete, and other server-round-trip actions in plain HTML with correct semantics, dropping the JavaScript and link-styled-as-button hacks that today break reader mode, context menus, and accessibility.

Notes: The concrete proposal: add `action` and `method` attributes to `<button>`, e.g. `<button action="/comments/123" method="DELETE">`, letting a button issue a network request and redraw the current context without a form or script. · Core distinction: links are destinations that browsers can re-contextualize (middle-click to new tab, hover preview, copy href, bookmark, share); buttons trigger actions in a fixed context and deliberately lack all those affordances. The author notes navigations can legitimately come from buttons (logout, search) and that many links (mailto, in-page anchors, downloads) are not navigations. · Worked example: a comment-edit form uses existing `formaction` for Save Draft plus proposed `action`/`method` buttons for Cancel (GET) and Delete (DELETE), reproducing the whole UX in HTML alone. · Named anti-pattern: styling an `<a href>` as a button (e.g. USWDS's `class="usa-button"`) to get no-JS navigation; the author says USWDS adds JS for spacebar activation but JS cannot fix context menus or reader-mode rendering, so links still look like links to some users. · Author claims HackerNews upvotes use links for what should be POST/PUT actions, calling it a 'wild violation of HTTP semantics,' and argues DELETE is the most common use case because it needs no extra data. No-JS operation is framed as a hard requirement, citing UK government sites. · This is an author-advocated proposal, not a shipped or standardized feature; the call to action is to like the Button Actions issue on GitHub.

### [Bad Apple but It's Traceroute](https://jssfr.de/2026-07-27-bad-apple-but-traceroute.html) — 4/10

A working demonstration that nftables can rewrite ICMPv6 responses per-packet, turning traceroute output into an attacker-controlled data channel a network operator could exploit to fake or animate hop paths.

Notes: The trick uses nftables numgen (an incrementing counter) to rotate the ICMPv6 source address on each generated destination-unreachable/admin-prohibited response, so a single node returns a different 'hop' address each time. · Requires setting sysctl net.ipv6.icmp.ratelimit=0 to defeat the kernel's default 1/s ICMPv6 egress rate limit, otherwise the animation stalls. · mtr merges multiple addresses per hop by default to signal multipath; the author applies a one-line patch to ui/net.c (forcing i = 0) so only one address shows per hop. An alternative is a shell loop around traceroute, or mtr's -E flag, but -E freezes on the first frame. · Pipeline: ffmpeg resamples the 'Bad Apple!!' video to 8 fps (125 ms/frame) and scales frames to 30x11 pixels; a Python script converts the PNGs into just over 1 MB of nftables rules. · Framed as a joke/art piece in the 'Bad Apple!!' tradition, which the author compares to running Doom as a benchmark for arbitrary hacked 'displays', including a prior character-LCD hack he cites.
