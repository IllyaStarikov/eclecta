### [Eight Bits of Trust; eMudhra's CA keys cracked in milliseconds](https://scotthelme.co.uk/eight-bits-of-trust-emudhras-ca-keys-cracked-in-milliseconds) — 8/10

If your scripts, CI runners, or embedded devices use default TLS settings, eight eMudhra CA keys that were literally the numbers 4, 56, and 115 let anyone on the network path forge a valid cert for any hostname, and revocation does not reach you.

Notes: Eight eMudhra intermediate CA private keys on the P-384 curve were single-byte integers; the author recovered all eight on a laptop in under a second: EM OV TLS CA-G3C was d=4, EM EV TLS CA-G3C was 56, EM EV TLS CA-G3B was 115, plus 155, 156, 230, and two code-signing keys 66 and 237. A correct P-384 key is a random 384-bit number (~2^384), so brute force needs at most 255 steps. · Six TLS issuing CAs (DV/OV/EV, two generations each) and two code-signing CAs, all created April 2025 and cross-signed by Sectigo's AAA Certificate Services root in May 2025, giving a 17-month exposure window where the keys were effectively public and no theft was needed. · Timeline: reported Saturday Oct 17 2026 to Apple, Google, Microsoft, Mozilla and eMudhra; Chrome shipped a CRLSet block that evening and Mozilla used OneCRL hours later; Mozilla announced publicly Tuesday Oct 20 with an NSS update removing the root, and the root goes in Chrome Root Store v43. · Browsers are largely protected because Chrome, Firefox and Safari require Certificate Transparency and block the intermediates directly; the author notes CT only detects mis-issuance, it does not prevent it, and no forged certs chaining to these CAs appeared in CT logs. · Non-browser clients (curl, Python, Node, Go, Java, git, package managers) trust an on-disk CA bundle and check neither revocation nor CT by default, so revocation does not help them. The author served a cert for api.stripe.com locally: curl reported 'SSL certificate verify ok', Python handshook, Node returned authorized:true on every Linux and macOS machine tested; Windows CryptoAPI accepted the chain unless revocation checking was enabled, and even then only one of two routes showed revoked. · The certificates pass every structural check (valid curve point, valid encoding); weakness is only found by trying to factor. Frozen-firmware IoT/OT devices trust these certs until expiry in July 2039. Per eMudhra's later account on the Mozilla bug, a ceremony script bug created a second weak keypair on the HSM and human error used the wrong keys for the CSR; the author adds that a single Claude prompt recovered the keys.

### [The bridge to agent-scale Git infrastructure](https://github.blog/engineering/architecture-optimization/the-bridge-to-agent-scale-git-infrastructure) — 7/10

If you push to GitHub from CI or coding agents, the write path just stopped serializing on a repo-wide lock: concurrent pushes to different branches now run in parallel and saw 3-4x higher throughput in GitHub's internal tests.

Notes: GitHub is migrating repo data from its own data centers to Azure, forced by agentic-era traffic growth against hard ceilings on data center power capacity and physical supply chain. First replica landed in Azure Central US in August 2025; most repos now keep two of their five replicas in Azure, and Azure serves about half of Git traffic. · The old Spokes quorum holds a repository-wide lock per write and waits for every healthy replica (up to a timeout) before moving on, so the slowest replica sets both latency and the throughput ceiling. A cross-region replica is ~1,000 miles / ~25ms per round trip, and a write needs multiple round trips, which the busiest ~0.00001% of repos could not absorb. · Fix: shrink quorum scope from the whole repository to individual Git references. Consistency only needs to hold per reference (no client sees an older value after an accepted update), so writes to different refs no longer wait on each other. Claimed 3-4x throughput at lower latency in internal testing with realistic traffic. · Next, read/write decoupling: data lands durably in Azure Blob Storage, which joins the quorum as a 'virtual replica,' a fully ephemeral bridge node that streams writes (a write is not acked until durable in object storage), serves no reads, coalesces disjoint-reference transactions into one set of object-storage I/Os, and currently runs compaction. · Virtual read replicas then scale out on demand, warming cache from Blob Storage and reconciling in the background without joining the quorum; repos run 100-1000 reads per write. Caveat: background reconciliation does not fit all read workloads, and the quorum remains the bound on further write throughput. · Spokes is more than a quorum: an intelligent routing/load-balancing layer and unified API handling 'well over 100 billion operations per day,' plus 'sweeper' background systems for placement, repair, and rebalancing. GitHub states the current commit protocol that reached a billion repos won't reach the next billion; the end-state design, including a remaining small consensus group, is promised in a follow-up post at GitHub Universe.
