### [eMudhra intermediate CA compromise](https://emudhra.we-have-a-problem.com/) — 8/10

Any non-browser TLS client that skips revocation checks, curl, Go, Node, Python, and the system trust stores behind them, keeps trusting eight impersonation-grade intermediates until you install the specific patched package versions listed here.

Notes: The private keys for eight eMudhra intermediate CAs can be recovered directly from their public certificates because of flawed key generation; the certificates chain to roots in the Mozilla, Microsoft, Apple, and Chrome programs, so holding any one key lets an attacker impersonate any website. · Exposure dates to April 2025 when the certs were created. There are no Certificate Transparency log entries for them in that window, so CT-enforcing browsers (Firefox, Chrome, Edge, Safari) could not have been attacked; the article states exploitation against non-CT-enforcing clients is unknown, not ruled out. · Reporter 'Wayne' proved compromise by signing 'We have a problem here - Wayne' with each intermediate's private key; proof.zip ships each cert, public key, and SHA-384 signature verifiable with openssl dgst. Disclosed to root programs Oct 17, downstream trust stores Oct 19. · Browser revocation landed Oct 17 (Firefox/Chrome via OneCRL/CRLite/CRLSets), Oct 19 (Apple), Oct 20 (Microsoft); eMudhra also revoked the intermediates. Clients that do not consume revocation data need software updates instead. · macOS blocks the intermediates system-wide, but built-in /usr/bin/curl verifies against /etc/ssl/cert.pem with no revocation check and that file was not updated; the page gives an awk command to strip the AAA Certificate Services and emSign ECC Root CA - G3 roots. · Patched versions are enumerated across the stack, Go 1.27.3/1.26.10, Python certifi 2026.10.19, Rust rustls-webpki 0.103.16, Electron 44.9.1, curl CA bundle 2026-10-20, distro ca-certificates packages, with Node.js, Bun, and FreeBSD ca_root_nss listed as pending. Page published by Dennis Jackson, source on GitHub.

### [Tsrs: A Port of TypeScript to Rust](https://blog.cloudflare.com/typescript-rust-port) — 8/10

If the benchmarks hold, type-checking a large TypeScript codebase gets up to 8x faster at ~70% less memory, and the no-GC Rust build makes running a full TypeScript toolchain in WebAssembly (browser, Workers, embedded) practical.

Notes: tsrs is a Rust port of the TypeScript compiler, built by Cloudflare and VoidZero with Max Schwenk of Owner.com, incubated inside the Oxc toolchain. Cloudflare says it is explicitly not a fork and that the TypeScript team keeps full control of language design. · Self-reported benchmark: tsrs is up to 8x faster and uses ~70% less memory than TypeScript 7.0 at equal type-check worker counts; Cloudflare says it worked with the TS team to match configurations. By default tsrs ships an adaptive config that trades more memory for even higher speed. · TypeScript 7.1 beta is already up to 2.5x faster than 7.0, with some optimizations upstreamed from tsrs. No methodology, machine specs, or codebase details are given for any of these numbers. · Rust was chosen over Go (the language of TS's own native port) mainly for WebAssembly: compiling Go to Wasm drags in its garbage collector, while Rust's memory model allows direct guest/host memory interaction. Cloudflare recently added native Rust in Workers via an Emscripten target for wasm-bindgen. · Maintenance plan copies Cloudflare's Vinext/Next.js sync: agents review upstream diffs each morning and open tracking issues, and a nightly run regenerates a compatibility matrix against the TypeScript test suite; performance wins are to be contributed back to the TS Go codebase. · Known gaps: behavior differs from upstream today (for example, the order diagnostics are printed); Cloudflare aims to minimize this before a stable release. Work with Theo Browne will merge tsc-rs and tsrs into one package supporting LSP and content mappers. Install via npm (npm install tsrs).

Notes: Interop (Google, Apple, Microsoft, Mozilla, plus Igalia and Bocoup) tends to bring a prioritized feature near 100% cross-browser within a year; cited precedent: CSS Subgrid shipped in Firefox 2019, stalled, then went widely available after being added to Interop 2023. Mozilla built a ranking/voting system for Interop 2027 and plans to use the data to pick focus areas. · @function lets authors define custom CSS functions with typed params, defaults, and a `result` value (e.g. polar-to-cartesian translate); already implemented in Chromium per the author. · corner-shape (squircle, bevel) and the lower-level border-shape (lines, arcs, Bezier curves, animatable) alter the actual border-box, so borders, outlines, and shadows trace the new shape, unlike clip-path or masks. As of October 2026 corner-shape is absent in Firefox/Safari. · Anchor Positioning Level 2 adds a container query to detect when a target used a fallback (flipped) position; base Anchor Positioning was in Interop 2026 and is now widely available. Other proposals: scroll-triggered animations (vs the already-shipped scroll-driven), reading-flow/reading-order to align tab order with visual layout, interpolate-size/calc-size() for height:0-to-auto animation (in Chrome since 2024), gap decorations (rule/row-rule/column-rule), and scroll-state container queries for stuck sticky elements and scroll position. · inherit() function (calc(inherit() - 4px) for nested radii) is the author's wishlist item but is implemented in no browser and not on caniuse; he expects it to miss Interop 2027. Author's framing of near-100% support and Chromium implementations is self-reported, not independently cited. · Author's closing argument: modern CSS still matters in the LLM era because model training data lags these features, so engineers must know them to steer agents toward progressive enhancement.
