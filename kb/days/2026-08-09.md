### [Zapscape (CVE-2026-64561): Guest-to-Host Escape in KVM/x86](https://github.com/V4bel/Zapscape) — 8/10

If you run multi-tenant KVM/x86 hosts that expose nested virtualization, a single rented VM can now reach host kernel root code execution, and the PoC and disclosure are already public.

Notes: CVE-2026-64561 ("Zapscape"), found by Hyunwoo Kim (@v4bel), is a use-after-free in KVM/x86 shadow MMU emulation, specifically the recursive zap path that runs when shadow pages are reclaimed; the quota-driven recursive zap has no root_count guard. · Guest-side actions alone trigger it: the author's chain switches long-mode to PAE to alias one shadow page as both child and pinned root, has L2 memory touches drive L0 quota reclaim into the recursive zap UAF, then escalates to L0 kernel code execution. · Affected commit range is f95eec9bed76 (2020-07-08) through 2abd5287f083 (2026-07-21). On Intel it is triggerable only when both EPT page-walk length 4 and 5 are exposed to L1; the AMD SVM/NPT case is broader. · The bug is in in-kernel KVM, independent of QEMU emulation, so clouds using their own VMM stacks are also exposed. It doubles as local privilege escalation on distros like RHEL where /dev/kvm is world-writable (0666). · The published PoC targets AMD and runs under QEMU TCG for safe testing (build 7.1.3 kernel from bundled kconfig, QEMU v9.2.0+); on success it creates root-owned /Zapscape on the host. The author states it is demonstration code, not a weaponized cloud exploit, but says porting L1 actions into a guest kernel module and matching host kconfig is 'not a difficult task' (his own characterization). · Distinct from Januscape (CVE-2026-53359): same shadow MMU subsystem, different root cause. Reported under a linux-distros embargo that has now ended, with details posted to oss-security.

### [CSS:the bomb inside your inbox](https://portswigger.net/research/css-the-bomb-inside-your-inbox) — 7/10

Notes: Gareth Heyes (PortSwigger) tested Yahoo Mail, AOL Mail, Fastmail, ProtonMail, Gmail, Outlook, plus Firefox and OpenAI's Atlas browser. The Outlook <label for> bug (targeting element IDs like RibbonModeToggle to open the ribbon and pin an attacker's message) was still unfixed at publication; at least three webmail clients allowed unfiltered label 'for' attributes. · Atlas prompt injection: ::before/::after content hides text from the user (rendered French shown), while a near-zero opacity block (opacity 0.00000001) feeds the LLM hidden 'debugging' instructions triggered by the word 'translate'. The payload exfiltrates the victim's name letter-by-letter by opening tabs to https://02.rs/debug#<LETTER>; per-letter URLs matched the model's own output, bypassing Atlas's tab-open confirmation. · Clipboard-to-webmail attack (spotted by James Kettle): pasting attacker HTML/CSS into contenteditable fields flashed page text red in AOL and Yahoo Mail, exposing a race condition where CSS is not sanitized in time. Browser behavior differs: Chrome rewrites inline <style> into style attributes, Safari drops styles, Firefox keeps inline style tags and background-image requests, making Firefox the best target. · Token exfiltration via nested attribute selectors: a 12-char hex Medium login token (e.g. token=c2e16a1781ed) is stolen by matching 5 chars at the start and 5 at the end plus multiple 5-char 'contains' chunks, using CSS nesting and :not() to shrink payload size; the two middle chars are reconstructed server-side by overlapping the chunks. ### [Message your other Claude Code sessions](https://code.claude.com/docs/en/cross-session-messaging) — 6/10
